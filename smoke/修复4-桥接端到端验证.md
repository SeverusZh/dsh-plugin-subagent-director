# 修复4：settings 桥接端到端验证记录（2026-08-14）

## 问题链（三次迭代的根因）
1. **settings-not-exposed**：apiproxy 白名单（dsh-host-apiproxy/lib/index.js:2410-2423,3470-3475），树外命名空间永远不进 Web 白名单（官方注释：settings.register 暴露是 deferred work）。
2. **connection.rpc 方案失败**：HostConnectionService 在 apply() 内自用、从不 ctx.provide（dsh-client-connection/lib/index.js:530-549），树外插件拿不到。
3. **typert 方案放弃**：无公开扩展点文档，逆向成本高。
4. **webServer 方案第一次失败**：树外插件 ctx.get('webServer') 不可见——官方 connection 插件用 inject=["webServer"]（lib/index.js:479）；用户自己的 dsh-yolo-mode 同样拿不到（其 /plugins/yolo-mode/* 路由在运行实例 404）。
5. **命名空间未注册（更深 bug）**：主条目 ctx.get('settings') 同样不可见 → installDirectorSettings 静默跳过 → 命名空间从未注册（curl mutate 曾返回 "settings namespace is not registered"）。

## 最终方案
- 主条目 subagent-director：inject = ['tools','subagents','llm','settings']（settings 服务在 web 与 headless bundle 均存在，已核验 base bundle patch 含 dsh-settings-file 行）——负责 settings 命名空间注册 + 快照 + 委派工具 + 指引。
- 新条目 subagent-director-bridge（exports "./bridge"）：inject = ['webServer','settings']——只负责自注册 HTTP 前缀路由 /subagent-director（webServer.register，kind:prefix），headless 下因 inject 不满足而自然不激活。
- 客户端无改动：rpc.call('/subagent-director', ...) 的 envelope 与应答语义按 dsh-client-connection/lib/client.js:10094-10113 与 lib/index.js:275-328 复刻（src/envelope.ts 纯函数）。

## 端到端验证（smoke-web，端口 3090，curl 实测）
- POST /subagent-director/settingsView → 200，result.ok=true，view.ns=subagent-director，含完整 schema 与 revision。
- POST /subagent-director/settingsMutate（set defaultModel=deepseek-v4-flash）→ 200 ok=true，返回新视图。
- POST /subagent-director/settingsMutate（unset defaultModel）→ 200 ok=true（还原）。
- method 不匹配 → 200 bad-request（message 指明 mismatch）。
- 服务器验证后已停止，3090 释放。
