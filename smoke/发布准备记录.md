## 5) 发布待办清单（建仓 → push → 设置公开 → npm publish）

以下脚本为**草案**，发布执行者需在确认后在本人会话内执行（本执行者已按红线跳过）。

### 0) 前置：登录与构建

```bash
npm login                 # 用户需先登录 npm（本次 npm whoami 未登录）
npm run build             # 确保 lib/ 是最新构建产物
npm test                  # 回归（当前 73 用例）
npm run typecheck         # 类型检查
```

### 1) GitHub 建仓

```bash
# 二选一：公开仓（开源推荐）
gh repo create SeverusZh/dsh-plugin-subagent-director --public --source . --remote origin --description "Subagent Director: choose LLM provider/model per subagent with role templates (DSH plugin)"

# 或：私有仓，之后手动改公开
# gh repo create SeverusZh/dsh-plugin-subagent-director --private --source . --remote origin

# 若需手动把仓库可见性设为公开（GitHub 网页 → Settings → Danger Zone → Change visibility → public）
# 或：gh repo edit SeverusZh/dsh-plugin-subagent-director --visibility public
```

### 2) push 到 GitHub 并打标

```bash
git branch -m main                        # 若默认分支不是 main
git add -A
git commit -m "chore(release): prepare v0.1.0 (LICENSE/CHANGELOG/README/pkg metadata)"
git push -u origin main
git tag v0.1.0
git push origin v0.1.0
```

### 3) 设置公开（如第 1 步为 private）

```bash
gh repo edit SeverusZh/dsh-plugin-subagent-director --visibility public
```

### 4) npm 发布

```bash
# 校验发布清单是否完整（应含 lib/、README.md、LICENSE、CHANGELOG.md）
npm pack --dry-run

# 发布（公开包）
npm publish --access public

# 或在发布前用 dry-run 元数据校验（npm 8+）
npm publish --dry-run
```

### 5) 发布后核对

```bash
npm view dsh-plugin-subagent-director versions
gh release create v0.1.0 --title "v0.1.0" --notes "$(sed -n 1,6p CHANGELOG.md)"   # 可选：关联 GitHub Release
```
