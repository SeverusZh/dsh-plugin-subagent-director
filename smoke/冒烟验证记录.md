## 1) 摘要

- 环境就绪：dsh CLI v0.1.0-rc.6 可用；`pnpm` 经 `corepack enable` 补入 PATH（v11.21.0）；`.credentials.yaml` 含 key **OPENCODE_GO_API_KEY**（另有 DEEPSEEK_API_KEY；未打印任何值）。
- 用官方路径创建并配置了全新 headless profile `smoke`（C:/Users/Sev/.dsh/profiles/smoke），bundles = `dsh-base` + `dsh-headless`，依赖 `dsh-plugin-subagent-director`，`cordis.patch.yml` 按 web 的 insert 写法插入插件。
- 首次运行 `dsh --profile smoke "<委派提示>"` **装载即失败**：`cannot get property "tools" without inject`。根因：插件 `inject = ['subagents','llm']`，但 `mount()` 里调用 `ctx.tools.register(...)` —— 缺少 `'tools'` 注入（比对 `dsh-tool-subagent` / `dsh-tool-ralph`，它们均显式注入 `'tools'`）。
- 为把缺陷与路由验证隔离，在 **smoke profile 内部**建立了一份补丁副本 `plugin-patched/`（把 `inject` 改为 `['tools','subagents','llm']`），profile 依赖指向该副本后重跑。**源码仓库 `lib/`、`src/` 均未被改动。**
- 补丁后冒烟成功：主代理按提示调用 `subagent_role`（role/provider 留空，显式 model=deepseek-v4-flash），子代理返回「2」并原样转述。会话日志证明子代理运行于 `opencode-go/deepseek-v4-flash`。

## 5) 判定

> 路由生效（有条件）—— 但有一个必须明确的前提：

- 插件在 headless profile 中能与 dsh-subagent（spawn transport）集成，`subagent_role` 工具可被主代理调用。
- 显式指定 model=deepseek-v4-flash 被正确传递并实际作用于子代理（证据见 §4.2）。
- **源码仓库「未打补丁」的构建产物存在装载缺陷**：`inject = ['subagents','llm']` 缺 `'tools'`，而 `mount()` 直接调用 `ctx.tools.register(...)`，导致装配即抛 `cannot get property "tools" without inject`。
  - 对照：`@deepseek-ai/dsh-tool-subagent` 与 `@deepseek-ai/dsh-tool-ralph` 的 inject 都显式包含 `'tools'`。本插件遗漏。
  - 本次冒烟通过 smoke profile 内隔离补丁副本（plugin-patched/，仅把 inject 加 'tools'）跑通；仓库源码/构建未被改动。

> 若以「仓库原样构建产物能否在全新 headless profile 端到端跑通」为准：**未生效 / 环境受阻：插件装载即失败**，原因 = inject 缺 'tools' 的插件缺陷。
> 若以「插件机制与模型路由本身是否成立」为准：在补上该缺陷后可端到端验证，**模型路由生效**。
