## 课题1：client 入口声明与加载机制

**结论**：插件 client 入口通过「loader entry 的 package.json 声明」被发现，无需专门注册表——条件是插件是 web profile 的活动 loader entry，且其 package.json 同时满足两点：
1. 声明 `dsh: { client: { platform: "web" } }`（可选 inject/immediately）——见 dsh-client-modules/lib/index.js:249-256（`parseDshClient`），平台非 "web" 则返回 null 跳过。
2. `exports` 提供 `"./client"` 子路径，指向**已构建**的 bundle 文件（接受字符串或 `{default}` 一层条件形式）——index.js:75-85（`clientExportOf`）、255（`clientRel = clientExportOf(pkgName, pkg.exports)`）、256 报错 "declares dsh.client but exports no ./client bundle"。

关键证据：
- `ClientModuleRegistry`（@deepseek-ai/dsh-client-modules/lib/index.js:121）注入 `["webServer","loader"]`；订阅 `ctx.on("internal/plugin")`（:140）收集 fiber 的 `entry.options.name` 为 dirty；激活时 `for (const entry of ctx.loader.entries()) dirty.add(entry.options.name)`（:153）；`flush`→`processOne`（:281-297）对每个 entry，若 loader 中存在同名且 `fiber!==undefined && !disabled` 的 non-group entry 则 resolveMeta。
- `resolveMeta`（:238-264）：用 `createRequire(ctx.baseUrl)` 的 `require.resolve("${spec}/package.json")` 读 package.json；clientPath = `join(dirname(pkgPath), clientRel)`。
- bundle 服务路由：`webServer.register({kind:"prefix", path:"/plugins", handler:this.serveBundle})`（:158-162）；`serveBundle`（:313-344）响应 `/plugins/<id>/client.js` 与 `.map`，以 `clientPath` 读文件。
- 每个 bundle rev = `shortHash(readFileSync(clientPath))`（sha1 前12位 hex，:87-89）；graph row url = `/plugins/<id>/client.js?rev=<rev>`（:91-99）。
- 期望的 `window.__DSH_BOOT__` 由 `injectBootManifest`（:100-113,：163 `tapIndex`）注入 head。

**浏览器端消费**（dsh-client-modules/lib/client.js）：解析 `window.__DSH_BOOT__`（:209-239）为 modules/plugins；`ClientModuleSystem`（:47）按 id 懒加载 bundle（script 加载后经 `window.__ModuleLoader__.load({id,factory})` 注册）；`import(specifier)`（:133-153）解析顺序 seed→memorize→static→factory→graph row；`stripClientSuffix`（:28）把 "<id>/client" 归一为 id。

**web profile 如何加载树外插件**（@deepseek-ai/dsh-app-boot/lib/index.js profile 段）：
- profile 目录 = `$DSH_HOME/profiles/<name>`（:309,318-321），含 `package.json`（依赖=树外插件 + `dsh.profile.bundles`）、`cordis.patch.yml`（用户 patch 层）、`pnpm-workspace.yaml`（:353-369 `initProfile`）。
- Loader `baseUrl` = profile 目录；模块解析双锚点：先 dsh 安装目录，后 profile 目录（:299-306）。
- `$DSH_HOME/profiles/node_modules` 扁平 fallback（:409-438 `healProfilesModuleFallback`）为 dsh app 依赖闭包建 symlink，使任何 in-box 插件可从任意 profile Node 解析。
- 行条目通过 `cordis.patch.yml` 的 `insert`（id/name/config）挂载插件；`name` = loader entry 名 = 包 specifier。见 dsh-web-app/cordis.patch.yml 的 "browser plugin roster (dsh.client rows)" 段（ui-settings-models 等行）。

**对我们 package.json 的要求**：
- `exports` 需含 `"./client"` 子路径（如 `{"types":"./lib/client.d.ts","default":"./lib/client.js"}` 或简单字符串），并指向构建后 bundle。**`exports["."]` 不影响 client 发现**——client 只看 `exports["./client"]`。
- 需声明 `dsh: { client: { platform: "web" } }`（manifest 顶层 `dsh.client`）。
- 需要在 web profile patch 中挂载 entry（树外场景即 `$DSH_HOME/profiles/web/cordis.patch.yml` + package.json dependency + pnpm 安装），并执行 `pnpm run build`（page 报 MissingClientBundleError 提示）。

**待确认**：ctx.baseUrl 是否就是 profile 目录（对本插件 clientPath 解析的实际影响）；lib/client.js 以 CJS factory 形式产出（`window.__ModuleLoader__.load`）；exports 条件导出是否被 `clientExportOf` 支持（答：只支持字符串或一层 default，无 types/import 条件）。

## 课题3：Locale 机制

**结论**：命名空间通过 \`declare module '@deepseek-ai/dsh-client-ui-slots' { interface LocaleNamespaceMap }\` 声明；用 \`ctx.locale.register(NS,{zh,en})\` 注册（双语文案强制平衡）；用 \`ctx.locale.bind(NS)\` 拿 typed \`t\`；slot 注册声明 \`locale: NS\` 后组件自动收到 typed \`t\` prop。

证据（@deepseek-ai/dsh-client-locale/lib/types/client/index.d.ts）：
- \`LocaleNamespaceMap\` 空接口先由 ui-slots 声明（ui-slots index.d.ts:27-28），各包经 declaration merging 增补（locale index.d.ts:18-25 例）。
- \`LocaleRuntime.register<N>(ns, dicts)\`（:134）typed 双语文案（zh 为 \`FALLBACK_LOCALE\`，:61，lookup 链 :68-70：entry 活跃→entry zh→common 活跃→common zh→key 本身）。重复 (ns,locale) 抛错。
- \`bind<N>(ns): TranslateNS<N>\`（:153）返回稳定引用 typed translate，可放 inject face（不破坏 memoization）。
- \`LocaleDictOf<N>\` = \`Record<LocaleNamespaceMap[N], string>\`，缺/多 key 编译错（ui-slots index.d.ts:62）；t key 域 = 命名空间 ∪ common（:48）。
- slot 组件经 \`PropsLocale<N>\` 拿 \`t\`（ui-slots index.d.ts:67-70），仅当注册声明 \`locale: N\`。
- \`common\` 由 locale 插件内置（index.d.ts:21-22, COMMON_NS= "common" :63）。

**我们做法**：声明 \`'settings.subagentDirector': SubagentDirectorKey\`，\`ctx.locale.register(NS,{zh,en})\`，register option \`locale: NS\`，组件 props \`t: TranslateNS<'settings.subagentDirector'>\`。新增 key 需同时加 zh/en（编译期强制）。

## 课题9：构建影响

**结论**：当前 tsconfig 无 JSX/DOM 配置，且 tsc 只产出普通 ESM，不是 DSH client 的 \`window.__ModuleLoader__.load\` 打包形态——这是 M2 最大构建缺口。

当前 tsconfig.json：\`lib:["ES2023"]\` 无 DOM、无 \`jsx\`、\`types:["node"]\`、\`rootDir:"src"\`→\`outDir:"lib"\`、\`verbatimModuleSyntax\`。
- 需要调整：加 \`"jsx": "react-jsx"\`；\`lib\` 加 \`"DOM"\`（\`"DOM","DOM.Iterable"\`）；\`types\` 需含 \`@types/react\`（或去掉 types 限制用自动 @types）；\`type: module\` 已输出 \`lib/client/index.js\`（ESM）。
- client 入口输出路径：现有 \`src/client/index.ts\` → \`lib/client/index.js\`（该文件现已存在但只是占位 ESM，缺 __ModuleLoader__ 封装）。\`exports["./client"]\` 应指向 \`./lib/client/index.js\`（或约定 \`./lib/client.js\`，取决于入口文件位置）。
- **关键缺口**：DSH client 加载器要求 bundle 是 \`window.__ModuleLoader__.load({id, factory})\` 的 CJS 形态（dsh-client-modules/lib/client.js:1-2, 71-75），且 scanner 要求 \`dsh.client.platform==='web'\`（index.js:249-256）。\`tsc\` 不会产出这种 bundle，也不会打包跨包 import（client bundle purity gate 禁止 cross-plugin value import，settings-scope.d.ts:80-82）。真实 DSH 客户端包用专用 build（源码注明的 \`tsdown.client.ts\`）产出 bundle。M2 需引入 bundler（rolldown/oxc 等，项目已有 \`@rolldown/binding-win32-x64-msvc\`、rolldown、lightningcss 在 node_modules）或等 harness 提供 client-package 构建模板。

## 课题10：风险与未知

- **R1 客户端 bundle 构建**：\`tsc\` 无法产出 DSH 要求的 \`__ModuleLoader__.load\` 单文件 bundle，且 client 需为单个打包产物（含 CSS 内联）。无源码 tsdown 模板可抄（DeepSeekHarness 是安装目录，只有 node_modules 编译产物，无 packages/ src）。**fallback**：复用项目 node_modules 里已有的 rolldown/rolldown-node-resolver/lightningcss；入口 wrapper 手动 \`window.__ModuleLoader__.load({id:pkg, factory})\`（需验证 cordis 客户端 require 语义）；或与 harness team 对齐官方 client 打包脚本。
- **R2 ctx.baseUrl / clientPath 解析**：\`resolveMeta\` 用 \`createRequire(ctx.baseUrl)\` 的 \`require.resolve("<pkg>/package.json")\`（client-modules index.js:138-139, 238-247）。ctx.baseUrl 是否为 profile 目录未从源码直接确认（只看到 profile bundle/baseUrl 设计注释 dsh-app-boot profile 段 :299-306）。**fallback**：入口 entry 名用与 package.json name 完全一致的 specifier，确保任一 baseUrl 都能 resolve；实测 web profile 的 dsh.client 扫描日志确认。
- **R3 树外插件安装路径**：本机 web profile（C:\\Users\\Sev\\.dsh\\profiles\\web）dependencies 为空，node_modules 目录不存在；smoke profile 用 \`file:\` 依赖打到了 harness 安装（E:\\DeepSeekHarness\\node_modules）。树外 client 插件要能被 web profile 扫描到，需进入 web profile 的 Node 解析闭包（profile/node_modules 或 flat fallback）。**fallback**：把插件加到 web profile package.json 依赖并 pnpm install，或在 profile 的 cordis.patch.yml 加 \`insert\` 行。
- **R4 现存占位 client 不是合法 bundle**：\`src/client/index.ts\` 占位已 build 为普通 ESM \`lib/client/index.js\`，且无 \`dsh.client\` manifest；即使配上 exports["./client"] 也无法被 client-modules 以 bundle 形式加载。M2 需重写 client 入口为合法 bundle 形态。
- **R5 settings span 命名空间**：本插件写 settings 需要注册自己的 settings namespace（\`ctx.settings\` / \`settings.namespace\`，参考 dsh-settings-file / llm-deepseek 的 \`llm-*\` 命名空间）。本调研未展开 Host 侧 \`ctx.settings\` 注册细节（非 client 侧）；M2 若写 settings 需另查 dsh-settings 包。
- **R6 exports 条件导出**：\`clientExportOf\` 只接受字符串或一层 \`{default}\`（无 types/import 条件，client-modules index.js:75-85）；\`exports["./client"]\` 用简单字符串或 \`{types,default}\` 均安全（types 会被当 default 忽略或需为字符串）。建议用 \`{"types": "./lib/client/index.d.ts", "default": "./lib/client/index.js"}\` 仍兼容（default 取到字符串），或直接字符串指向 bundle。
